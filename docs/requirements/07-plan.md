## 16. リスクと対応

起きうる問題と、その扱いを決めておきます。「受け入れる」は、問題が起きうることを発注者が承知のうえで、対策をしないことを意味します。

| No | リスク | 影響 | 対応 |
| --- | --- | --- | --- |
| R-03 | 複数のタブで操作して、内容が失われる | 小 | 受け入れる。1つのタブで使う前提とする（P-03） |
| R-06 | dnd-kit などのライブラリの開発が止まる | 小 | 版を固定しているため、今のまま動き続ける（NFR-28） |
| R-07 | ブラウザの更新で動かなくなる | 小 | 問題が出たら受入テストをやり直して確認する |
| R-08 | データベースが壊れる・消える | 大 | 定期的にバックアップを取る（12.4）。最後のバックアップ以降の変更は失われることを受け入れる |
| R-09 | サーバーの起動を忘れて、アプリが開けない | 小 | 障害時の対応表（12.5）で案内する |
| R-10 | 同じWi-Fiのほかの人に見られる | 中 | 自分のパソコンからの接続だけを受け付ける（NFR-21） |
| R-13 | 新しく覚える技術（React・Spring Boot・JPA・PostgreSQL）が多く、動くまでに時間がかかる | 大 | 最初に3つの部品がつながる最小の形を作り（ステップ2）、そのあと機能を1つずつ足す。1ステップごとに動作を確認する |
| R-14 | PostgreSQL が動いていない・パスワードが違うなどで、サーバーが起動しない | 中 | 障害時の対応表（12.5）で案内する |
| R-15 | データベースのパスワードを、うっかりGitに入れてしまう | 中 | パスワードは環境変数に入れ、設定ファイルには書かない（12.1）。コミットの前に差分を見る。入れてしまったらパスワードを変える |
| R-16 | 画面を変えたのにビルドし忘れて、`http://localhost:8080` で古い画面が出る | 小 | 障害時の対応表（12.5）で案内する。開発中は5173番で確認する（12.6） |

※ R-01・R-02・R-04・R-05・R-11（ブラウザ保存とフェーズ1に関するもの）、R-12（言語・データベースの決定の遅れ）は v2.0 で削除（欠番）。

## 18. 開発ステップ

各ステップの終わりに動作を確認し、Gitでコミットします。ステップ2で「画面・バックエンド・データベースがつながった最小の形」を先に作り、ステップ3からは、そこに機能を1つずつ足していきます。

- [ ] **ステップ1: 開発環境を用意する**（12.1 の1〜3、Q-05）
  JDK・Node.js・PostgreSQL・VS Code の拡張機能を入れ、データベース `taskboard` を作る
- [ ] **ステップ2: 3つの部品をつなぐ**
  Spring Initializr でバックエンド、Vite でフロントエンドの雛形を作る。データベースにつながったバックエンドが返す文字を、`http://localhost:5173` の画面に表示できる
- [ ] **ステップ3: テーブルを作り、ボードを表示する**（9.3、API-01、F-01）
  Flyway でテーブルと最初の3つのリストができ、画面に3つのリストが並ぶ。幅に入りきらないときは下の段へ折り返す
- [ ] **ステップ4: カードを操作する**（API-05〜07、F-05〜07、F-10）
  カードの追加・編集・削除ができ、データベースに保存される。サーバーを止めて起動し直しても残っている
- [ ] **ステップ5: ドラッグ&ドロップ**（API-08、F-08・F-09）
  dnd-kit でカードを別のリストへ移したり、並べ替えたりでき、開き直しても移動先にある
- [ ] **ステップ6: リストを操作する**（API-02〜04、F-02〜04）
  リストの追加・名前変更・削除ができる
- [ ] **ステップ7: 期限・優先度・並べ替え**（API-06・API-09、F-11〜13）
  カードに期限と優先度を付けられ、リストの中を期限順・優先度順に並べ替えられる
- [ ] **ステップ8: エラーに備える**（10章、NFR-14・NFR-22）
  バックエンドの入力チェックとエラーの返事、画面の赤いメッセージと読み込み直しができている
- [ ] **ステップ9: ふだん使える形にする**（8.1、12.1 の4、12.2）
  画面をビルドして Spring Boot から配り、`http://localhost:8080` だけで使える
- [ ] **ステップ10: 運用の準備をする**（12章）
  バックアップと復元を実際に試し、手順書どおりにできる
- [ ] **受入テスト**（15章）

画面の見た目は、画面プロトタイプ（`prototype/`）を参考にします。

## 19. 今後の拡張案

完成後に余裕があれば、次の順で機能を増やします。

1. カードを削除した直後の「元に戻す」
2. カードにラベル（色）・詳細メモ（改行あり）を付ける（期限・優先度は v1.4 で本体に入れた）
3. リスト自体の並べ替え（ドラッグ&ドロップ）
4. 画面からのバックアップ（ファイルへの書き出し・読み込み）
5. カードの検索
6. 複数ボードの切り替え（ER図に boards テーブルを追加する）
7. スマートフォン表示への対応
8. 自動テストの導入（バックエンドは JUnit、画面は Vitest）
9. インターネットへの公開（ログイン機能が必要になる）
