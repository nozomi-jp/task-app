# 要件定義書 ① 概要・スコープ・前提

[← 目次・要約に戻る](README.md) ｜ 主に読む人：発注者・開発者

---

## 1. 概要

リストとカードでタスクを管理する、Trello風のシンプルなWebアプリを作ります。

- **目的**: タスクを「ToDo / 進行中 / 完了」などの列で見える化し、状況をひと目で把握できるようにする
- **背景**: AIエンジニアコースの課題として、要件定義から実装、データベースを使った運用までの流れを一通り体験する
- **対象ユーザー**: 自分ひとり（個人のタスク管理）。ログインや共有は想定しない

### 1.1 進め方

画面（React）、バックエンド（Java・Spring Boot）、データベース（PostgreSQL）の3つを、最初から組み合わせて作ります。

| 項目 | 内容 |
| --- | --- |
| 保存先 | データベース（バックエンド経由） |
| 開き方 | サーバーを起動して `http://localhost:8080` を開く |
| ゴール | 画面と操作を完成させ、日々の運用（起動・停止・バックアップ）ができる |

v1.4までは「フェーズ1：ブラウザ（localStorage）に保存」「フェーズ2：データベースに保存」の2段階でしたが、v2.0で技術の指定（13章）を受けて1つにまとめました。いきなり全部を作るのではなく、18章の開発ステップで**最初に3つの部品がつながる最小の形を作り**、そこに機能を1つずつ足していきます。

## 2. スコープ

| 区分 | 内容 |
| --- | --- |
| 作る | ボード1枚、最初の3つのリスト（ToDo・進行中・完了）の表示、リストの追加・名前変更・削除（v2.27〜v2.29 で追加）、カードの追加・編集・削除（削除は元に戻せる。v2.24 で追加）、カードのドラッグ&ドロップ移動・並べ替え（キーボードでもできる。v2.19 で「作らない」から変更）、カードの期限・優先度（高・中・低）、期限順・優先度順の並べ替え、カードの検索（v2.25 で追加）、カードのラベル（色。v2.26 で追加）、データベースへの自動保存、バックエンド（API）、運用手順（起動・停止・バックアップ・障害時の対応） |
| 作らない | ログイン、マルチユーザー（複数人での利用・共有・同時編集）、複数ボード、担当者、期限の通知、リスト自体の並べ替え、元に戻す（カードの削除以外）、画面からのバックアップ機能、スマートフォン表示、インターネットへの公開 |
| 今回の文書で扱わない | 納期、費用、保守（課題のため） |

## 3. 前提条件・制約条件

**前提条件**は「これが成り立っている前提で作る」こと、**制約条件**は「変えられない制限」です。前提が崩れたときに起きる問題は、16章「リスクと対応」で扱います。

### 3.1 前提条件

| No | 内容 |
| --- | --- |
| P-01 | 利用者は自分ひとりで、1台のパソコン（Windows）で使う |
| P-02 | ブラウザは Chrome か Edge を使う |
| P-03 | 1つのタブで使う |
| P-04 | 使う前に、自分でサーバーを起動し、ブラウザで `http://localhost:8080` を開く（12.2） |
| P-06 | 最初に1回だけ、開発・実行に必要なソフト（JDK・Node.js・Docker Desktop。PostgreSQL は Docker で動かす）を入れる。このときだけインターネット接続が必要（12.1） |

※ P-05 は v2.0 で削除（ブラウザに保存しなくなったため）。番号は詰めずに欠番にしています。

### 3.2 制約条件

| No | 内容 | 理由 |
| --- | --- | --- |
| C-01 | 画面は React で作る。Next.js は使わない | 発注者の指定 |
| C-06 | バックエンドは Java と Spring Boot で作る | 発注者の指定 |
| C-07 | データベースは PostgreSQL を使う | 発注者の指定 |
| C-02 | 動かすときに、外部のサイト（CDNなど）からファイルを読み込まない。ライブラリは npm・Maven で入れて、アプリに含める | ネットにつながっていなくても動かすため |
| C-03 | 自分のパソコンの中だけで動かし、インターネットには公開しない | ログイン機能を作らないため（公開すると誰でも見られてしまう） |

※ C-04「サーバー・データベースを使わない」、C-05「モジュール機能を使わない」は v2.0 で削除（欠番）。

## 4. 用語集

| 用語 | 意味 |
| --- | --- |
| ボード | アプリの画面全体。リストを並べる台 |
| リスト | 「ToDo」「進行中」などの列。カードを縦に並べる |
| カード | タスク1件。文字と、期限・優先度を持つ |
| 確定 | 入力した内容を反映すること。カードのダイアログの「保存」ボタン、またはタイトルの欄でEnterキー（6.1） |
| ドラッグ&ドロップ | カードをマウスでつかんで動かし、離して置く操作 |
| フロントエンド | ブラウザで動く部分（画面）。React で作る |
| バックエンド | サーバーで動く部分。画面からの依頼を受けて、データベースを読み書きする。Spring Boot で作る |
| API | 画面とバックエンドがやりとりする窓口。「このURLにこの形のデータを送ると、こうなる」という約束 |
| データベース（DB） | データを表（テーブル）の形で保存する仕組み。PostgreSQL を使う |
| テーブル | データベースの中の表。1行が1件のデータ |
| ER図 | テーブルと、テーブル同士のつながりを表した図 |
| React | 画面を「部品（コンポーネント）」に分けて作るための、JavaScriptのライブラリ |
| TypeScript | JavaScript に「型」（この値は数か文字か、などの決まり）を書けるようにした言語。書き間違いを、動かす前に見つけられる。ファイルの拡張子は `.ts` |
| JSX・TSX | Reactで画面の形を書くための書き方。プログラムの中にHTMLのような形で書ける。TypeScript で書くときのファイルの拡張子は `.tsx`（JavaScript なら `.jsx`） |
| Vite | Reactの画面を開発中に表示したり、完成品のファイルにまとめたり（ビルド）する道具 |
| ビルド | 書いたプログラムを、動かせる形のファイルにまとめること |
| npm | JavaScriptのライブラリを入れる道具。Node.js に付いてくる |
| Spring Boot | Javaでサーバーを作るためのフレームワーク |
| Maven | Javaのライブラリを入れたり、ビルドしたりする道具 |
| JPA | Javaのクラスとデータベースのテーブルを対応させて、SQLを書く量を減らす仕組み |
| マイグレーション | テーブルを作る・変えるSQLを、番号付きのファイルにして順に実行する仕組み。Flyway を使う |
| オリジン | ブラウザが「同じサイトかどうか」を見分ける住所。`http://localhost:8080` と `http://localhost:5173` は別のオリジン |
| localhost | 自分のパソコン自身を指す名前。`http://localhost:8080` は「自分のパソコンの8080番の窓口」という意味 |
| ポート | パソコンの中の窓口の番号。8080、5432など |
| トランザクション | 複数の書き込みを「全部成功」か「全部なかったことにする」のどちらかにする仕組み |
