## 14. 受入基準

受入テスト（15章）の「必須」の項目がすべて合格したら、完成と認めます。「任意」の項目は、不合格でも完成とします（優先度「中」の機能に関わるもの）。ただし、期限と優先度の基本の操作（AT-45・AT-49・AT-50）は、優先度「中」の機能ですが「必須」とします（発注者の判断、v2.19）。

- テストは、`http://localhost:8080`（Spring Boot から開く）で行う。開発サーバー（5173番）では行わない
- テストは、データがない状態から順に行う。ふだんのデータを消さないように、テスト専用のデータベース `taskboard_test` を同じ Docker の中に作り、環境変数 `SPRING_DATASOURCE_URL` でつなぐ先だけを変えてサーバーを起動する（ポートは 8080 のまま）。終わったら `taskboard_test` を消す（v2.22 で「`taskboard` を作り直す」から変更）
- 動作環境（NFR-04）の確認として、AT-10・AT-18・AT-22は Chrome・Edge の両方で行い、それ以外は Chrome で行う

試し方の補足：

- データベースの中身（AT-35・54・60〜62 など）は、pgAdmin の代わりに SQL で見た
- AT-12 の「貼り付け」と AT-45 の「カレンダーから選ぶ」は、プログラムで文字・日付を入れて試した（AT-45 のカレンダーは、発注者が AT-58 と一緒に確かめた。合格）
- AT-22・53 の「ブラウザを閉じる」は、ブラウザを終わらせて、同じ設定のまま開き直した
- AT-23・33 は、再起動の前とあとで、データベースのリストとカードがまったく同じことも SQL で確かめた。Docker Desktop は操作していない
- AT-25 は、Wi-Fi を切っていた間（18:24:44〜18:25:55）にカードの変更が保存されたことも、Windows の記録とデータベースの更新日時（18:25:31）で確かめた
- AT-28 は、500枚で、追加・編集・削除・移動のどれも 0.2秒以内だった（NFR-01。遅かったのは編集の 0.194秒）
- AT-42 は、iPhone で、ほかのウェブサイトは見られる状態で開けなかった（1回目は読み込み中のまま長くかかり、2回目は「iPhoneがインターネットに接続されていないため」の文が出た）。2回目の文が出た理由と、そのときの Wi-Fi の名前は確かめていない。そこで、パソコン側でも、サーバーが `127.0.0.1` だけで待っていること、パソコンの Wi-Fi の IP アドレスの8080番への接続が断られることを確かめて、合格とした
- AT-43 は、`taskboard_test` で、12.4 の `pg_dump`・`pg_restore` を使った（データベースの名前だけ変えた）
- AT-64 は、1回目のデータでは優先度の1回目が低い順になった。期限を遠い順にしたら、たまたま優先度も高い順になるデータだったためで、F-13 の決まり（今の並びを見て、もう並んでいれば反対にする）どおり。たまたまそろわないデータで試し直して合格とした
