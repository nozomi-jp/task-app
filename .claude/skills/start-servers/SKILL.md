# サーバーを決まったポートで起動して確認する

このアプリには、サーバーが2つあります。

| サーバー | ポート | 起動するフォルダ | コマンド | 起動できた合図 |
| --- | --- | --- | --- | --- |
| バックエンド（Spring Boot） | **8080** | `backend` | `.\mvnw.cmd spring-boot:run` | `Started TaskboardApplication` |
| 画面（Vite の開発サーバー） | **5173** | `frontend` | `npm.cmd run dev` | `Local:   http://localhost:5173/` |

## なぜポートを固定するのか

ポートは、この2つのサーバーがお互いを見つけるための住所です。画面の開発サーバーは `/api` を `127.0.0.1:8080` へ中継し（`frontend/vite.config.ts`）、ユーザーはブラウザで `http://localhost:5173` を開きます。どちらかが別のポートで動くと、中継がつながらなかったり、ユーザーが古いサーバーの画面を見て「直っていない」と勘違いしたりします。また、確かめたつもりのものが、ふだん使う形と違ってしまいます。

そのため、先生と発注者の決まりで、**別のポートで一時的に起動するのも禁止**です。ポートがふさがっているのは、たいてい前に起動したサーバーが残っているだけなので、それを止めて同じポートで起動し直すのが正しい直し方です。

この決まりは、ほかのしくみでも守られています。
- フック `.claude/hooks/guard-ports.sh`：別のポートを指定する起動（ポート指定のオプション、`server.port` の上書き、`SERVER_PORT`）、`strictPort` を外すこと、設定ファイルのポートの書き換えを止める
- `frontend/vite.config.ts` の `strictPort: true`：5173 がふさがっていると、別のポートへ逃げずにエラーで止まる。Spring Boot も 8080 がふさがっていればエラーで止まる

フックに止められたら、回り道を探さず、この手順に戻ってください。

## 手順

### 1. データベースが動いているか確かめる

バックエンドは起動時に PostgreSQL（Docker、5432 番）につなぎます。先に確かめておくと、起動に失敗したときに原因を迷いません。

```bash
docker compose ps
```

`db` が `healthy` ならOK。なければリポジトリのフォルダで `docker compose up -d`。5432 は下のスクリプトの対象外なので、ふさがっていても止めないでください（Windows 版 PostgreSQL のサービスが動いている可能性があり、それはユーザーに相談します）。

### 2. ポートを確かめ、ふさがっていたら空ける

リポジトリのフォルダで、同梱のスクリプトを実行します。

```powershell
./.claude/skills/start-servers/scripts/free-port.ps1 -Port 8080
./.claude/skills/start-servers/scripts/free-port.ps1 -Port 5173
```

（Git Bash からは `powershell -NoProfile -ExecutionPolicy Bypass -File .claude/skills/start-servers/scripts/free-port.ps1 -Port 8080`）

- 空いていれば「空いています」と出るだけで、何もしません
- ふさがっていれば、使っていたプロセス（PID・名前・コマンド）を表示して止め、空いたことを確かめます
- 8080・5173 以外は指定できません。Windows 自身（PID 0・4）も止めません
- 「止められません」「まだ空きません」と出たら、それ以上は何もせず、ユーザーに相談します

**止めたら、何を止めたかをユーザーに必ず伝えてください。** ふさいでいるのは、ユーザーが自分のターミナルで起動したままのサーバーであることが多いからです。黙って止めると、ユーザーは自分のサーバーが急に終わった理由がわかりません。

プロセスを止めてよいのは、このスクリプトで 8080・5173 を空けるときだけです（発注者が 2026-11-21 に許可）。`Stop-Process`・`taskkill` を直接使うことは、これまでどおり禁止されています。

### 3. 起動する

確認のために Claude が起動するときは、ツールの「バックグラウンドで実行」（run_in_background）を使い、ログをファイルに書き出して、上の表の「起動できた合図」が出るまで待ちます。

- バックエンド：`backend` で `.\mvnw.cmd spring-boot:run`（データベースのパスワードは環境変数 `TASKBOARD_DB_PASSWORD` から読む）
- 画面：`frontend` で `npm.cmd run dev`

起動が「Port 8080 was already in use」「Port 5173 is already in use」で失敗したら、手順2に戻ります。別のポートを試さないでください。

### 4. 確かめる

目的に合わせて、たとえば次のように確かめます。

```bash
curl -s http://localhost:8080/api/board      # バックエンドが直接答えるか
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:5173/   # 画面が返るか（200）
curl -s http://localhost:5173/api/board      # 画面の開発サーバーの中継を通ってAPIに届くか
```

### 5. 後片付け

自分がバックグラウンドで起動したサーバーは、確認が終わったら TaskStop で止めます。そのあと手順2のスクリプトをもう一度実行し、ポートが空いたことを確かめます（`npm.cmd` や `mvnw.cmd` の子のプロセスが残っていることがあり、残っていればスクリプトが空けます）。ユーザーのサーバーを残したままにしておくと、次にユーザーが起動するときにポートがふさがってしまうからです。

## ユーザーに起動してもらうとき

ユーザーはプログラミングを学び始めたばかりです。次のように書きます。

- 「VS Code の上のメニュー → ターミナル → 新しいターミナル」から書き始める
- `cd` と次のコマンドは別のコードブロックに分け、「左の `PS ...>` が変わったのを確かめてから次へ」と添える（2行がつながって入力されたことがある）
- PowerShell では `npm` ではなく `npm.cmd` と書く（スクリプトの実行が止められる設定のため）
- 2つのサーバーを動かすときは、ターミナルを2つ使うことと、それぞれの「起動できた合図」を書く
- 止め方（Ctrl + C、バックエンドは `Y` → Enter も）を最後に書く

ユーザーが「ポートが使われている」というエラーを見たときは、手順2のスクリプトで Claude が空けるか、「前に起動したターミナルで Ctrl + C」と案内します。

## してはいけないこと

- 8080・5173 以外のポートでサーバーを起動する（一時的にでも）
- 8080・5173 以外のポートを使っているプロセスや、5432（データベース）を止める
- `application.properties` の `server.port`、`vite.config.ts` の `port`・`strictPort` を書き換える
